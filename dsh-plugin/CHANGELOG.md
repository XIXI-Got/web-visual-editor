## 1.1.55（按原元素单位决定映射）
- 保存前检测元素原始 CSS 单位：

- 宽度映射为父容器百分比（无父级用 vw），高度同理，字号映射为 `clamp()`。
- 不再“一刀切”把所有元素都转比例，也不再所有元素都写死 px。


## 1.1.54（编辑器覆写层改为比例）
- 保存时不再把 `width/height/font-size` 以 px 写进 `.ve-data`：
  - 宽：父容器百分比（无父级时 vw），并自动加 `max-width:100%; box-sizing:border-box`
  - 高：父容器百分比（或 vw）
  - 字号：`clamp(min, vw, max)`
- 拖动产生的尺寸（box）也先转成相对宽高，再写入覆写层；位置保留少量 translate。
- 这样编辑器加载的覆写本身就是相对值，不会再一打开就把整页锁死。

## 1.1.48（拖拽改尺寸后可撤销）
- 拖拽/缩放时为了跟手，临时给元素写了 inline `width/height !important`；结束拖拽原来只还原 transform，尺寸的 inline 值留着，撤销时样式表改不回来。
- 现在 beginDrag 记录原始 inline 宽高，endDrag 还原/移除；撤销能正确恢复容器/元素的尺寸。
- `unlockFlexSize` 不再单独占一步历史，改宽高只产生一步，撤销一次即可。


## 1.1.47（容器锁只锁宽度/位置，高度可调）
- 容器锁不再拦高度：section/header/footer 等结构容器仍禁止横向拖动和改宽，但拖上下边、改高可以正常使用。
- 改宽输入框仍会拦截；高度输入框放行。


## 1.1.46（修复应用脚本的无限重绘）
- `ve-applied.js` 的 MutationObserver 每次都会重设 `textContent`，触发新的 DOM 变更 → 无限循环，页面持续重绘、截图挂起；现在文本相同就跳过写入。
- 同时修复 `blockText` 的同类问题。


## 1.1.45（固化后同步源码 hash）
- 固化会向 HTML 注入 `ve-applied.js`，源码 hash 随之变化；现在固化结束会同步更新各页面 `source-meta.json`，避免下次打开编辑器被误判为“外部修改”而归档覆写。
- 本次 demo 的文案修改已应用到 `ve-applied.js`，只写入文字，没有宽高/位置。


## 1.1.44（源码变更自动归档旧编辑）
- 每次加载编辑器覆写前，先比对页面源码 hash；如果源码被外部改过（例如重新设计 CSS），把旧 overrides 自动备份到 `.ve-data/backups/`，同时保存一份最新源码快照，然后清空旧覆写、读取最新源文件。
- 首次打开记录 `source-meta.json`；保存时自动更新。
- 编辑器会 toast 提示「源文件已被外部修改：旧编辑记录已备份并停用」。


## 1.1.43（文字容器不再写死宽高）
- 「应用到源码」对 p / h1-h6 / span / a / button / li 等文字元素不再写 width/height（也不写 left/top），只保留字号/颜色等；文字容器可以随内容和窗口自适应，也不会在编辑器里被覆写锁住。
- 清理 demo 中 p 的 20.938vw × 4.463vh 固定尺寸。


## 1.1.42（去掉横向滚动条）
- 1.1.41 把拖动位移换成 `left/top` 的 vw/vh 百分比，静态元素向右偏移会把页面推出窗口，产生横向滚动条；现在不再把位移写入源码。
- 宽度百分比写入时同时加 `max-width:100%` 和 `box-sizing:border-box`，避免 padding 把宽度撑出窗口。
- 清理了 demo 里已生成的 left/top 覆写。


## 1.1.41（布局改动按比例写入）
- 保存时记录参考尺寸：编辑时的视口 `vw/vh` 和父容器 `pw/ph`，随覆写一起存。
- 「应用到源码」把绝对像素换算成相对值：
  - 宽：`w / 父容器宽 × 100%`（无父容器信息时 `w / 视口宽 × 100vw`）
  - 高：`h / 父容器高 × 100%`（或 `vh`）
  - 拖动位移：`x / 父容器宽 × 100%` 写成 `left`，`y` 写成 `top`
  - 外边距/内边距 px → 百分比；字号 px → `clamp()`
- 例：1920 宽下 480px 宽 → 25%；1280 宽时自动变 320px，而不是继续 480px。


## 1.1.40（「应用到源码」相对化）
- 「固化到源码」改名为「应用到源码」，行为改为**追加相对/响应式样式**，不覆盖原 CSS 文件；不满意可直接删除 `ve-applied.js` 还原。
- 字号：px 自动转成 `clamp(px*0.7, 当前px/vw, px*1.12)`，随窗口缩放。
- 宽度/高度/位置/位移：绝对 px 不写入；百分比、vw、rem、clamp 保留。
- 这样应用后不会再出现“整站被一个固定 px 尺寸带歪”的情况。


## 1.1.39（固化不再写死布局）
- 「固化到源码」现在会剔除 width/height/left/top/transform/position/flex/grid、font-size/line-height/letter-spacing 以及 box 位移，只保留颜色、字重、圆角、padding 等视觉样式；不会再生成固定 px 把文字/容器锁死。
- 编辑器注入的覆写 CSS 改为追加到 body 末尾，顺序上压过已有的 ve-applied.js，元素即使被旧固化样式卡住也能在编辑器里继续调整。
- 配合容器锁：结构层仍默认锁定，文字/段落等普通元素可正常拖动和改尺寸。


## 1.1.38（容器锁只锁结构层）
- 只锁页面骨架（section/header/footer/nav/main）、多列 grid/flex 容器、section 下的 `.wrap`；普通文字容器（p、div 文本块、按钮等）不再被锁。
- 修正上一版把很多文本容器也拦住的问题。


## 1.1.37（容器布局锁）
- 新增「🔒 容器锁」快捷开关，默认开启：`section/header/footer/nav/main` 以及 `.wrap/.hero-grid/.product-grid/.qgrid/.feats/.foot` 等容器禁止拖动/缩放，避免误拖把固定 px 写进页面、破坏自适应。
- 锁定状态下改宽/高输入框也会拦截并提示；需要时可点按钮解锁（解锁后仍会按你的修改保存）。
- 锁定偏好记在 localStorage。


## 1.1.36（父容器占满行并居中）
- 快捷操作新增「⇔ 父级占满行」：把当前元素的父容器设为 `width:100%; max-width:none`，若父容器本身是 grid/flex 子项则跨满整行，然后对当前元素做响应式居中。
- 解决“元素在左栏里居中，只相对半栏居中”的问题；实测 h1 父列跨满 1184px 后，标题中心 = 页面中心 640（1280 宽）。


## 1.1.35（响应式居中同时居中文字）

- 换窗口宽度仍保持居中（实测 1280→900，h1 文字居中、盒子随父容器居中）。

## 1.1.11（找到圆角不圆的真正原因：DSH 主题的 squircle）

- **根因**：DSH 主题插件全局注射了 `@supports (corner-shape: superellipse(1.5)) { :root{--dsw-corner-shape:superellipse(1.5)} *,:before,:after{corner-shape:var(--dsw-corner-shape)} }`——所有元素默认用 **squircle（超椭圆）圆角**。DSH 自己的按钮都会写 `corner-shape: round` 退出这个效果，我们的插件 UI 没写，所以 `border-radius:999px` 被画成了"圆角矩形"：**computed 是 999px，看着却不圆**（这也解释了为什么 1.1.8/1.1.9 的 `!important`、inline 修正都无效）
- **修复**：插件所有 UI 根节点及其后代（预览面板 / 抽屉 / 原生 tab / 弹窗 / 菜单 / 浮动 pill / 侧边入口按钮）统一 `corner-shape: round !important`，恢复标准圆角，和工作台里看到的一致
- 测试：harness 里模拟 DSH 的全局 squircle 规则，断言插件按钮 computed `corner-shape` 必须是 round（`superellipse(1)`）；另加源码级断言防止以后被改回去
