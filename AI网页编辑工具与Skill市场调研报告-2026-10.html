结论先行（TL;DR）

  1. 「AI 能接入」和「AI 能改网页」是两件事。绝大多数产品（Lovable / v0 / Bolt / Same / 各类 AI 建站）是 从零生成新站；把 URL 丢进去得到的是重建的副本，不是原地修改。真正能改「你已有的线上页面」的只有三条路：平台官方 MCP、代码库内可视化编辑、浏览器扩展注入渲染层。
  2. 目前工程上最干净的闭环是「CDP + MCP」：读结构化 DOM（不是截图）→ AI 产出 CSS/HTML diff → evaluate_script 注入 → 截图/录屏验证。chrome-devtools-mcp（54k★，Apache-2.0，免费）能同时给出渲染结果和源码行号，是这条路的首选；playwright-mcp 的 annotate/highlight 是做「用户圈一下、AI 来改」交互的现成积木。
  3. 平台侧已经 MCP 化，而且能改线上页：Webflow 官方 MCP（所有计划含免费 Starter，能改建页/样式/组件/CMS/交互，带分支与快照）、Elementor 4.3 官方 MCP（2026-09-22 内建）、WordPress 7.0 Abilities API + EMCP / GoBuildWP（带快照与回滚）。存量站改造优先看这条线。
  4. 「Skill」补的是方法，不是手段。Anthropic 的 Agent Skills 标准已在 2026-10-22 捐给 Linux 基金会 AAIF，70+ 平台接入、100 万个 skill、约 2.8 亿次安装；但官方 skill 里只有 frontend-design、web-artifacts-builder、webapp-testing 等「产出 + 验收」能力，没有任何一个「打开既有网页 → 精准改 DOM/源码」的专用 Skill。Skill 没有浏览器和网络能力，碰不到页面。
  5. 这块市场很小、很新、很不稳。唯一的「网页可视化编辑 MCP」项目只有 0 star、467 下载/月、单人维护；另有大量包名重名（canvas-agent 其实是 Canvas LMS 教学 MCP）。做选型必须假设「半年后可能没了」。
  6. 国内基本空白。没有「贴 URL 就让 AI 改线上页面并保存」的厂商级产品；能落地的只有：① AI IDE 改本地仓库（Trae / CodeBuddy / Qoder CN / Comate）② 平台内生成物（秒哒 / Coze / 微搭 / CodeWave）③ 浏览器扩展临时改渲染层（刷新即失、不可发布）。

一、先分清 4 种「AI 改网页」的真实含义

市面上把这些混在一起讲，是选型踩坑的第一原因。它们的能力边界、失败模式、成本完全不同：

层级含义谁是玩家能否持久化典型失败
L0 运行时改渲染往当前页面注入 <style> / DOM 改动，立即生效浏览器扩展（PageStyler、ReSkin）、CDP evaluate_script不能，刷新即失MV3 被回收、SPA 路由切换丢状态
L1 改源码AI 读仓库 → 改组件 → 重新构建Trae / CodeBuddy / Cursor / Claude Code / Onlook能（进 Git）需要拿到源码，线上站多半拿不到
L2 平台内改结构通过 CMS / 建站平台的官方 MCP 或 API 改Webflow MCP、Elementor MCP、EMCP、Builder.io能（落草稿→发布）只作用于该平台托管的站
L3 像人一样操作截图/无障碍树 + 点击输入，替人干活Claude in Chrome、ChatGPT 云浏览器、Comet不落源码定位失败静默报成功；不提供「注入任意 CSS」通道

关键判断：Skill 没有「手」。Skill 是提示词 + 脚本资产包，本身不携带浏览器与网络能力；要碰到页面必须有 MCP / CDP / 扩展。所以「AI 改网页」的正确组合是：MCP 给手段（读 DOM、截图、注入）+ Skill 给方法（设计规范、验收流程、组件约定）——这也是 AAIF 的官方口径（MCP 与 Skills 互补）。判据一句话：「知道怎么改但没有手」→ 上 MCP；「有手但每次改出 AI 味」→ 上 Skill。

十二、选型建议（按场景）

1「我的网站，改了要发布」 → 平台官方 MCP：Webflow MCP（免费 Starter 就能用，带分支/快照）/ Elementor 4.3 MCP（限 Atomic V4）/ WordPress + EMCP 或 GoBuildWP（带回滚）。没有官方 MCP 就退回 D：源码进 Git，用 AI IDE 改。

2「就把当前这个页面改好看点，不用发布」 → 浏览器扩展（PageStyler 那套）或 CDP evaluate_script 注入。零依赖、即时预览、成本最低。

3「我要自研一个『AI 网页调整工具』」 → 交互外壳用 MV3 扩展（WXT + Shadow DOM 隔离），能力层接 chrome-devtools-mcp 或自建 CDP 桥；产出受限的结构化 JSON/CSS patch（不要直接执行 LLM 生成的脚本），走「CSS 清洗白名单 + 撤销/重做 + 差异导出」。底座可参考 GrapesJS（能吃任意 HTML）或 Puck（React/JSON）。

4「批量/跨站自动化」 → browser-use / Stagehand / Steel（自托管最省）。

5「给非技术同事用」 → Claude in Chrome（已 GA、付费档内含、零采购）；但它只会「像人一样点」，改不了样式，真要改还得接 MCP。

6「只改自己仓库里的页面」 → 其实不必上 MCP：项目级 SKILL.md（设计规范 + 组件约定 + 验收清单）+ 支持 Skills 的 IDE（CodeBuddy / Claude Code / Cursor），token 最省、可进 Git 版本管理。

十四、市场空白与产品机会（给做「网页调整工具」的团队）

  • ① 「改任意已有网页」的产品级 MCP 是真空。唯一沾边的项目 0★、467 下载/月、单人维护；大厂（Anthropic / OpenAI / Google）都止步于「像人一样点」。做「DOM 结构化读 + 受限写回 + 截图验证」这三件套，就能填上这个洞。
  • ② 运行时与持久化之间的断点没人补。预览在 DOM、持久化在源码——中间的 diff/patch 导出（CSS patch、JSON patch、PR、设计 token 映射）是明显缺口。web-editor-mcp 只做了 JSX/TSX，Vue / Svelte / 纯 HTML 全覆盖无人做。
  • ③ 安全是准入门槛，也是卖点。Anthropic 实测提示注入攻击成功率 23.6%；现有扩展普遍直接执行 LLM 输出。把「CSS 清洗白名单（禁 expression()/javascript:/@import/外部 url）+ 只允许 JSON 规则 + 撤销重做 + 隐私裁剪」做成默认，就比大多数竞品稳。
  • ④ 国内市场几乎真空。国内只有「临时改渲染层」的小插件，没有产品级厂商；同时国内 AI IDE 已支持 MCP / Skills 的分发渠道（CodeBuddy、Trae），缺的是「改网页」这个能力件本身。
  • ⑤ 团队协作 / 审批流缺位。Webflow 的 draft + branch + 「AI 活动日志」是目前的标杆；非平台型工具基本没有「谁改的、能不能回滚、谁批准发布」。
  • ⑥ 别和大厂抢「像人一样操作」。Claude in Chrome 已 GA 且含在付费档，Comet 免费；正面竞争无胜算。差异化在「精确改样式 + 可回滚 + 可交付」。
